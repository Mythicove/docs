- 日期：2026-10-22

## 背景

Modrinth 在 2024 年把代码从 AGPL-3.0 改成 source-available（非 OSI 开源），是"被人白嫖后闭源"的前车之鉴。需为各仓库选型防同类问题。

初版选 AGPL-3.0（网络服务 Copyleft）。2026-10-24 复审：项目本意是**反商用**（防止他人把本站作为商业托管服务牟利），而非强制衍生品开源；AGPL 的 Copyleft 反而抬高了启动器/插件/企业自托管等生态接入门槛，与"统一前端 + 启动器生态"的目标相悖。同期调研了 Commons Clause、ELv2、FSL、BUSL、SSPL 与"AGPL+双授权"六条路线。

## 决策

| 资产 | 许可证 | 理由 |
|---|---|---|
| 产品（`mythic-mirror`/`mythic-hoard`/`web`/`mythic-compass`） | **Elastic License 2.0（ELv2）** | 源码可用：允许使用/修改/分发/自用商用；**禁止把产品作为托管/管理服务提供给第三方**（即反商用的精确命中点）；禁止绕过 license key、禁止去除版权 notice |
| 共享 Go 模块（`shared`） | **Elastic License 2.0（ELv2）** | 属产品核心代码，非公共 SDK，与产品一致 |
| 契约与生成物（`api`） | **MIT** | SDK/契约类走宽松许可，便于第三方启动器/工具接入 |
| 文档内容（`docs` 的文字/图片） | **CC BY-SA 4.0** | 文档标准许可证 |
| 文档站代码（`docs` 的 Astro 配置/样式/组件） | **MIT**（2026-10-27） | CC 系列明确不建议用于软件；站点代码属工具性质，与 `api` 一致走宽松许可，仓库内以 `LICENSE`（内容）+ `LICENSE-CODE`（代码）双文件标注 |

## 理由

- **意图对齐**：ELv2 的三条限制中"不得作为托管/管理服务提供"正是"反商用（云厂商/竞品开站牟利）"的法律表达；其余使用（自托管、企业内部、二次开发、客户端集成）全部放开，生态门槛低于 AGPL。
- **文本质量**：ELv2 短、plain-language、有 Elastic 等大规模商用先例；相较 Commons Clause（"Sell" 边界模糊、无判例、OSI/FSF 明确不认）与 FSL/BUSL（带"若干年后自动转开源"的日落条款，与"永久反商用"意图不符），ELv2 是最贴合且最严谨的选择。
- **诚实标注**：ELv2 属 source-available，**不是 OSI 开源**。README/文档不再使用"开源"表述描述产品代码，避免误导。

## 后果

- 正：反托管牟利有明确条款；生态接入（启动器/插件/自托管）无 Copyleft 负担；条款短易读。
- 负：失去"开源项目"身份标签（OSI 定义下）；若未来想靠"开源社区"获客需重新评估；换证仅对**换证后发布的版本**生效，此前以 AGPL 发布的版本（v0.1.0~v0.3.0 tag）保持 AGPL（本项目为单一作者，无外部贡献者，故可单方面对后续版本换证）。各换证仓库根目录附 `LICENSE.history`，说明现行/历史许可证、换证提交、旧 tag 归属与实际影响（GitHub 不会自动识别该文件，仅作对外说明，许可证以 `LICENSE` 为准）。
- 执行提示：许可证不能替代运营手段——商标登记、站点 ToS、以及对外托管实例的取证/下架流程仍是实际防线。
